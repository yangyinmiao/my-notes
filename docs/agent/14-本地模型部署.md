# 本地模型部署

> 目标：理解如何在本地运行开源大模型，不依赖云端 API，保护数据隐私。

---

## 一、为什么要本地部署？

| 需求 | 说明 |
|------|------|
| **数据隐私** | 企业内部数据不能传到第三方 API |
| **降低成本** | 高频调用时本地推理比 API 便宜 |
| **离线可用** | 无网络环境也能运行 |
| **定制化** | 可以微调、修改模型行为 |

---

## 二、主流工具对比

| 工具 | 定位 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| **Ollama** | 一键运行本地模型 | 最简单，命令行友好，自带 OpenAI 兼容 API | 定制性弱 | 个人开发、快速验证 ✅ |
| **llama.cpp** | 高效 C++ 推理引擎 | 极低内存，支持 CPU 推理 | 需要编译，使用复杂 | 资源极度受限的环境 |
| **vLLM** | 高性能 GPU 推理服务 | 吞吐量最高，支持并发 | 需要 GPU，配置复杂 | 生产级高并发场景 |
| **LM Studio** | 桌面 GUI 应用 | 图形界面，0 代码 | 只适合个人体验 | 非技术用户体验模型 |

## 三、Ollama 快速上手

### 安装

```bash
# macOS
brew install ollama

# Linux
curl -fsSL https://ollama.com/install.sh | sh
```

### 拉取并运行模型

```bash
# 运行 Qwen2.5 7B（中文效果好）
ollama run qwen2.5:7b

# 运行 Llama3.2 3B（轻量，适合低配机器）
ollama run llama3.2:3b

# 后台启动服务（不进入交互）
ollama serve
```

### 查看已下载模型

```bash
ollama list
ollama ps       # 正在运行的模型
```

### 删除模型

```bash
ollama rm qwen2.5:7b
```

## 四、Ollama OpenAI 兼容 API

Ollama 自带与 OpenAI 完全兼容的 API，只需改 base_url：

```python
from openai import OpenAI

# 指向本地 Ollama
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"          # 随便填，Ollama 不校验
)

response = client.chat.completions.create(
    model="qwen2.5:7b",       # 填 ollama list 中的模型名
    messages=[
        {"role": "user", "content": "你好，介绍一下自己"}
    ]
)
print(response.choices[0].message.content)
```

**在 LangChain 中使用**：

```python
from langchain_ollama import ChatOllama

llm = ChatOllama(model="qwen2.5:7b", temperature=0)
result = llm.invoke("报销单的审批流程是什么？")
```

## 五、模型选型指南

### 按任务选

| 任务 | 推荐模型 |
|------|---------|
| 中文对话 / 理解 | `qwen2.5:7b` 或 `qwen2.5:14b` |
| 代码生成 | `qwen2.5-coder:7b` 或 `deepseek-coder-v2` |
| 轻量/快速 | `qwen2.5:3b`、`llama3.2:3b` |
| 本地 Embedding | `nomic-embed-text`（Ollama 支持）|

### 按硬件选

| 内存 | 推荐规格 |
|------|---------|
| 8GB RAM | 3B~7B 量化模型（Q4） |
| 16GB RAM | 7B 全精度 或 14B 量化 |
| 32GB RAM | 14B~32B 量化 |
| GPU 8GB VRAM | 7B 全精度（float16） |

## 六、量化详解

量化 = 用低精度数字存储模型权重，显著减少内存占用：

| 量化级别 | 精度损失 | 内存节省 | 说明 |
|---------|---------|---------|------|
| FP32 | 无 | 0% | 原始精度，最大 |
| FP16 | 极小 | 50% | 训练常用 |
| INT8 | 小 | 75% | 推理主流 |
| Q4_K_M | 中 | ~87% | GGUF 常用，性价比最高 ✅ |
| Q2_K | 大 | ~93% | 内存极度受限时用，效果明显下降 |

**Ollama 默认下载 Q4 量化版本**，是内存和效果的最佳平衡点。

## 七、流式输出（Streaming）

生成速度慢时，流式输出可以让用户即时看到内容：

```python
# OpenAI API 流式
stream = client.chat.completions.create(
    model="qwen2.5:7b",
    messages=[{"role": "user", "content": "解释一下 RAG 技术"}],
    stream=True
)

for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)

# LangChain 流式
for chunk in llm.stream("解释一下 RAG 技术"):
    print(chunk.content, end="", flush=True)
```
