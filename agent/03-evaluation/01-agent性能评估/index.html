    Agent 性能评估¶

    目标：理解从哪些维度评估 Agent，用什么方法评，主流 Benchmark 在测什么。

    一、为什么 Agent 评估比 LLM 评估难¶

    LLM 评估是"输入→输出"的一次性打分，Agent 评估要面对：

    • 多步执行：每一步都可能出错，且错误会级联放大
    • 工具调用：不只看回答质量，还要看工具选择是否正确
    • 不确定性：相同输入每次执行路径可能不同
    • 开放路径：完成任务的方式有很多，没有唯一标准答案

    二、评估维度框架¶

    从两个视角组合：能力维度（能做什么）+ 质量维度（做得怎么样）

    能力维度¶

    能力 评估内容 对应模式
    规划能力 能否将复杂任务分解为可执行步骤 Plan-and-Execute、ReAct
    工具使用 从大量工具中正确选择并调用 Function Call、MCP
    记忆管理 多轮对话中上下文是否连续一致 短期记忆 / 向量检索
    反思与自评 执行中发现错误后能否自我纠正 Reflection 模式
    意图追踪 多轮交互中用户目标动态变化时是否跟得上 HITL / 对话管理
    主动澄清 指令模糊时是否能主动提问而不是乱猜 对话策略
    跨场景泛化 在陌生领域组合任务时能否迁移能力 Multi-Agent / RAG

    质量维度¶

    维度 关键指标
    准确性 任务完成率、工具调用正确率、最终答案准确率
    效率 完成任务所用步数、Token 消耗、延迟
    鲁棒性 异常/歧义输入下的成功率，是否无限循环
    安全合规 拒绝有害指令率、护栏触发准确率
    一致性 多次执行相同任务结果稳定性

    三、主流评估方法¶

    1. 基于规则的自动评估¶

    对有标准答案的任务（如数学、代码），直接比对输出结果。 - 优点：快、客观、可重复 - 缺点：只适合答案封闭的任务

    2. LLM-as-Judge¶

    用一个更强的 LLM 对 Agent 输出打分或比较。

    评估 LLM 收到：
- 原始任务描述
- Agent 的完整执行轨迹（每步 thought + action + observation）
- 评分标准（rubric）
→ 输出：分数 + 理由
    • 优点：能处理开放式任务，接近人类判断
    • 缺点：存在位置偏差、与评估 LLM 本身能力绑定

    3. 基于评分标准的滑动窗口评估器（Rubric-based Sliding Window Evaluator）¶

    VitaBench 提出的方法，专门解决随机交互导致评估不稳定的问题：

    将执行轨迹分成滑动窗口片段
↓
每段独立对照 rubric 打分
↓
汇总得到最终分数

    核心优势：不依赖单一标准路径，支持多种正确解法，同时对每段执行质量精细评估。

    4. 人工评估¶

    对高复杂度任务，由领域专家评判。成本高，通常作为自动评估的验证手段。

    四、VitaBench：真实场景 Benchmark¶

    论文：VitaBench: Benchmarking LLM Agents with Versatile Interactive Tasks in Real-world Applications（arXiv:2509.26490）

    核心设计¶

    项目 说明
    场景 外卖配送 / 线下消费服务 / 在线旅行
    工具数量 66 个
    跨场景任务 100 个（主评估集）
    单场景任务 300 个
    评估方法 Rubric-based 滑动窗口评估器

    核心评估项¶

    1. 时空推理：跨时间和空间维度的多步推理
    2. 工具选择：66 个工具中准确识别并组合调用
    3. 主动澄清：模糊任务时是否主动提问
    4. 意图追踪：多轮对话中动态跟踪用户目标
    5. 跨场景泛化：将不同领域能力组合使用

    测评结论¶

    任务类型 最强模型成功率
    跨场景任务 约 30%
    单场景任务 低于 50%

    即使是当前最强的模型，在真实复杂场景下表现依然很差。这说明现有 Agent 离"生产可靠"还有很大距离。

    五、Agentic Design Patterns 中的评估相关模式¶

    参考：Agentic Design Patterns（Antonio Gulli，Springer）中文译本

    设计模式 与评估的关联
    Reflection（反思） Agent 自我评估能力的核心，通过反馈循环迭代改进输出
    Goal Setting & Monitoring 动态追踪任务进展，评估目标达成率
    Evaluation & Monitoring 直接对应性能评估体系，量化 Agent 表现
    Guardrails（护栏） 安全合规性评估，防止不当行为
    Error Handling & Recovery 鲁棒性评估，系统在异常下的恢复能力

    六、评估流程参考¶

    1. 明确任务类型
   ├── 封闭型（有标准答案）→ 自动规则评估
   └── 开放型（多种正确路径）→ LLM-as-Judge 或 Rubric 评估器

2. 收集执行轨迹
   完整记录：输入 → Thought → Action → Observation → 最终输出

3. 多维度打分
   准确性 + 效率 + 鲁棒性 + 安全性

4. 分析失败原因
   ├── 工具选错 → 工具描述/参数校验问题
   ├── 无限循环 → 缺少终止条件
   ├── 意图漂移 → 上下文管理不足
   └── 幻觉调用 → 模型能力或 Prompt 问题
